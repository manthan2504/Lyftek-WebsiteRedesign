# 99_GLOBAL_RULES.md

# Global Rules

## Purpose

This document defines the non-negotiable principles that govern every aspect of the Lyftek website redesign project.

These rules apply to every task, regardless of whether it involves research, design, frontend development, content, architecture, motion, accessibility, or optimization.

If a recommendation conflicts with these rules, these rules take precedence.

---

# Think Before Building

Never begin implementation immediately.

Always:

Understand

↓

Research

↓

Analyze

↓

Compare

↓

Evaluate

↓

Implement

↓

Review

↓

Refine

Do not skip any stage for substantial work.

---

# Multi-Agent Collaboration

Every non-trivial task must begin by creating an internal team of relevant experts.

Examples include:

- Product Strategist
- Business Analyst
- Design Director
- Senior Product Designer
- UX Researcher
- Information Architect
- Brand Strategist
- Senior Frontend Architect
- Senior React Engineer
- Senior Next.js Engineer
- TypeScript Specialist
- Motion Designer
- GSAP Specialist
- Framer Motion Specialist
- Performance Engineer
- Accessibility Specialist
- SEO Specialist
- QA Engineer
- Enterprise Copywriter

Assign only the experts required for the current task.

Each expert should independently evaluate the problem before contributing to the final recommendation.

The final output should represent a coordinated team decision rather than a single perspective.

---

# Research First

Before making important decisions:

Research independently.

Consult:

- Official Documentation
- Approved Skills
- Approved MCPs
- Design Systems
- Enterprise Websites
- Technical References

Never rely on assumptions when authoritative information is available.

---

# Never Copy

Use inspiration only to understand:

- principles
- hierarchy
- spacing
- typography
- interaction
- architecture
- usability

Never recreate another company's website.

The goal is to build Lyftek's own identity.

---

# Business First

Every recommendation must support at least one business objective.

Always ask:

- What business problem does this solve?
- Why does this improve trust?
- How does this improve usability?
- How does this support conversion?
- Does this help enterprise decision-makers?

Business value always comes before visual trends.

---

# Design First

Design decisions should prioritize:

- clarity
- simplicity
- hierarchy
- consistency
- readability
- professionalism
- accessibility

Avoid unnecessary decoration.

Every visual element should have a purpose.

---

# Enterprise Mindset

Remember the audience.

Primary users include:

- CEOs
- CTOs
- Founders
- Enterprise Buyers
- IT Managers
- Business Owners

Design for confidence rather than entertainment.

Avoid startup clichés and trend-driven interfaces.

---

# Engineering Principles

Prefer:

- simplicity
- modularity
- maintainability
- scalability
- accessibility
- performance

Avoid unnecessary complexity.

Build systems that remain easy to evolve.

---

# Design System

The Design System is the single source of truth.

Do not introduce:

- random colors
- inconsistent spacing
- arbitrary border radius
- new typography
- one-off components

Update the Design System before introducing new patterns.

---

# Accessibility

Accessibility is mandatory.

Never sacrifice accessibility for aesthetics.

Every implementation should support:

- keyboard navigation
- screen readers
- semantic HTML
- focus visibility
- sufficient contrast
- reduced motion

---

# Motion

Motion should improve usability.

Never animate purely for decoration.

Prefer subtle, purposeful interactions.

If an animation does not improve the experience, remove it.

---

# Performance

Performance is a feature.

Always optimize:

- images
- fonts
- rendering
- JavaScript
- bundle size

Avoid unnecessary dependencies.

---

# Technology Decisions

Do not introduce new libraries without justification.

Before adopting any dependency:

Research

↓

Compare

↓

Evaluate

↓

Justify

↓

Implement

Favor mature, actively maintained solutions.

---

# Continuous Improvement

Question the first solution.

Look for opportunities to improve:

- UX
- accessibility
- performance
- maintainability
- scalability
- clarity

Refine before finalizing.

---

# Documentation

Whenever a significant decision is made:

- document the reasoning
- maintain consistency across the project
- update affected documentation when necessary

Documentation should evolve alongside the project.

---

# Project Status Tracking

After completing every meaningful task, update the project's status document.

The status document should record:

- Date or milestone
- Completed work
- Files created or modified
- Important decisions
- Design changes
- Engineering changes
- Pending tasks
- Known issues
- Risks or blockers
- Recommended next step

Before starting any new task:

Read the current STATUS.md file.

Use it to understand:

- current project progress
- previous decisions
- unfinished work
- implementation context

Treat STATUS.md as the project's shared memory and source of continuity between work sessions.

---

# Definition of Done

No task should be considered complete until it is:

✓ Researched

✓ Reviewed

✓ Accessible

✓ Responsive

✓ Production Ready

✓ Performance Optimized

✓ Design System Compliant

✓ Business Aligned

✓ Technically Sound

✓ Documented

---

# Final Principle

The objective is not to generate designs or code.

The objective is to create an enterprise-grade digital experience that reflects Lyftek's expertise, earns the trust of business decision-makers, and serves as a long-term foundation for the company's digital presence.

Every decision should move the project closer to that goal.
